# Strahlender Installer 0.1.5

Turns your own *Pokémon Brilliant Diamond / Shining Pearl* files into a native app on macOS, Linux and Windows.<br>Pick your system, start the installer, drop in your files, follow the build.

> [!TIP]
> 🇩🇪 **Strahlender** = *brilliant*: the same word as in *Brilliant Diamond*.

> [!NOTE]
> **iPhone and iPad:** iOS and iPadOS builds are part of the macOS installer.<br>They are built on a Mac with Xcode and your device connected.

## Download

| System | File | Start |
| --- | --- | --- |
| **macOS** · Apple Silicon and Intel | `Strahlender-Installer-macOS-universal.zip` | Unzip, open *Strahlender Installer* |
| **Linux** · x86_64 | `Strahlender-Installer-x86_64.AppImage` | Make it executable, run it |
| **Linux** · ARM64 (experimental) | `Strahlender-Installer-aarch64.AppImage` | Make it executable, run it |
| **Windows** · x86_64 | `Strahlender-Installer-x86_64.exe` | Run it, nothing to unpack |

> [!IMPORTANT]
> **macOS:** The installer is not notarized by Apple, so the first start shows:<br>*"Strahlender Installer" Not Opened: Apple could not verify "Strahlender Installer" is free of malware.*
>
> That is expected. If you do not trust the installer, you do not have to: the whole [source code](https://github.com/Veemyu/strahlender-xnu) is public.<br>Read and analyze everything yourself. No tracking, no hidden code.<br>Allow the app once:
> 1. Try to open the app and click *Done* (not *Move to Bin*).
> 2. Open *System Settings → Privacy & Security*, scroll down and click **Open Anyway**.
> 3. Confirm with your password and click *Open*. From then on it starts like any other app.
>
> If macOS says the app is *damaged*, see the technical details below.
>
> **Windows:** The installer is not code-signed. SmartScreen may show *Unknown publisher*.<br>Choose *More info → Run anyway*.

## What is new

**Windows**
- Much shorter build paths ([#28](https://github.com/Veemyu/strahlender-xnu/issues/28), [#49](https://github.com/Veemyu/strahlender-xnu/issues/49), thanks u/erest0r). The build folder name shrinks from 60 to 26 characters and the compiled files use shorter names, so the default folder fits for user names up to about 20 characters. The installer keeps its own data in one short folder, `%APPDATA%\str-xnu`, instead of `%APPDATA%\Veemyu\strahlender-xnu-installer\data` (30 characters less, the default build folder is 78 instead of 108 characters for a 5 character user name). Your installer settings are copied over on the first start; the old folder stays, and the game and your saves are not touched. Before, a default folder failed with *270 of 260 characters*.
- The path check at the start of a build now counts the game's deepest file too, so a too deep folder is reported at the start and not after the extraction.
- Builds from an older installer keep working with stored tools and bundles (no more *profile/inventory mismatch*).
- Reinstalling over an app from an earlier build works: the last step no longer stops with *not this installer's unchanged Windows package* after a complete build.
- *Install tools* can no longer be pressed again while the tools are downloading and unpacking, and the note about security software no longer claims it is checking game files at that point.
- Two installer windows can no longer break each other's *Install tools* (*WinError 3 ... license-texts*): one window prepares the tools while the other says so, and a failed setup shows the end of its error output in the log.
- Set `BDSP_INSTALLER_DATA_DIR` (for example `C:\bdsp`) to move the build folder to a shorter place.
- Name entry works without Switch firmware: a simple on-screen keyboard is drawn with a system font ([#37](https://github.com/Veemyu/strahlender-xnu/issues/37)).

**All systems**
- The installer log is also written to a file (the newest 10 sessions in the `logs` folder of the installer's data folder), so it survives a crash or a closed window.
- The log starts with your system details (version, platform, memory, disk space, graphics, tools), and a failed Install tools step stays on screen with its error, the step it stopped in, Copy log and Try again.

**macOS**
- Macs with 8 GB of memory and a 4 GiB Metal buffer limit (for example MacBook Neo) no longer close the game after 0.6 seconds with *cannot wrap guest heap in a Metal buffer* ([#48](https://github.com/Veemyu/strahlender-xnu/issues/48), thanks AkiraChnl). Game builds already pick this up from `main`; not verified on such a Mac.

**Linux**
- The game starts from its own folder without the launcher script and finds `img/`, `romfs/` and `main.npdm` next to the executable ([#26](https://github.com/Veemyu/strahlender-xnu/issues/26)).
- Opening folders from the installer works on desktops without `xdg-open` (falls back to `gio`; [#35](https://github.com/Veemyu/strahlender-xnu/pull/35), thanks antonioag95).
- The firmware step builds its decryption tool with the right target ([#33](https://github.com/Veemyu/strahlender-xnu/issues/33)).

**iPhone and iPad**
- Installing with a mod: every copy stages its own loose files ([#38](https://github.com/Veemyu/strahlender-xnu/issues/38)).

## Known limits

- Installers 0.1.4 still create the long 60 character folder. Install 0.1.5 to get the shorter paths.
- macOS 14 and 15 are targeted but were not run on such a Mac. Please tell us if the app does not start there.
- Windows mod apps keep the 16:9 interface for the files a mod replaces.
- A rare start crash on the Mac ([#2](https://github.com/Veemyu/strahlender-xnu/issues/2)) was seen once in about 300 starts. Start the app again.

## What you need

- Your own `prod.keys` and the base game.
- Optional: the game update. **Update 1.3.0 is preferred.**
- Optional: your Switch **firmware**.<br>It enables the native on-screen keyboard and other Switch firmware features (system fonts, keyboard layouts).<br>The installer finds firmware installed by common emulators; your dump stays unchanged.

The downloads contain no game files, keys or firmware.

<details>
<summary>Technical details</summary>

- **Game builds** download the current `main` source when a build starts.<br>The installer itself is versioned separately.
- **Updates:** the installer checks for newer releases.<br>It verifies an Ed25519-signed manifest before replacing itself (macOS app, Linux AppImage, Windows `.exe`).
- **Windows:** one executable.<br>Runtime, build tools and helpers are inside it and unpack to `%APPDATA%` on first start.<br>Qt, FFmpeg and SDL3 are fetched from their publishers on first use.
- **Linux:** where FUSE is unavailable, run the AppImage with `--appimage-extract-and-run`.
- **macOS "damaged" message:** download the file again and compare it with `SHA256SUMS` (`shasum -a 256 <file>`).<br>Only if the checksum matches, remove the download flag with `xattr -dr com.apple.quarantine "Strahlender Installer.app"`,<br>then open the app again.
- **Privacy:** no telemetry.<br>The installer contacts GitHub (updates, source code) and, when you install them, the publishers of the build dependencies.
- **Checksums:** `SHA256SUMS`. Every download is built on its native architecture in GitHub Actions.

</details>
