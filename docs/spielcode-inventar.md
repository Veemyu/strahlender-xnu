# Game-code inventory (IL2CPP dump)

Original analysis of `work/il2cpp/dump.cs` (types, base classes, namespaces) and `work/il2cpp/script.json` (method entries). Generated by `scripts/dump_stats.py` using only the standard library, streaming in about two seconds with less than 50 MB RAM. Only counts and names are recorded here; no code from the dump or `opendpr`.

## Interpretation and limitations

- **Types** means classes, structs, enums, and interfaces in the dump, including nested types: 11,812 total.
- **Compiler-generated helpers** (lambda containers, iterator state machines, `<>c`) are included and listed separately.
- **Methods** means `ScriptMethod` entries, assigned by the class prefix before `$$`, with generic arguments removed. Of 107,604 entries, 99.9% map to a dump type.
- Nested types lack namespaces in the dump; they are assigned to their enclosing type's namespace.
- **Generic** BCL method counts (`List`, `Array`, `Dictionary`, enumerators) are heavily inflated by instantiations, each with its own entries. They do not measure game-code size.
- Modules are assigned by namespace prefixes and naming patterns. Types without namespaces (a large game-assembly group) are classified approximately: Wwise and Pia/Ilca by name, remainder as game logic.
- Inheritance checks use short names. Collisions are possible; counts are reliable only in order of magnitude.

### Assessment: game logic versus engine/middleware

- **To reconstruct:** About 6,200 game types and 39,000 method entries. Excluding BCL instantiations (roughly 65,100 non-BCL methods), this is about **60%** of methods; 53% of all dump types, or 76% of the game assembly (6,213 of 8,157; the remainder is Wwise, NEX/Pia, data, networking).
- **Main areas:** Battle (`Dpr.Battle.*`, 1,816 types, 12,575 methods), UI (`Dpr.UI`, 1,232 types, 7,723 methods), global field/entity classes (935 types, 6,613 methods), `Dpr.Contest`, Secret Base, Underground, Pml (Pokémon parameters, move/personal data).
- **Sequences:** `Dpr.SequenceEditor` has 629 types but only 736 methods: mostly command/data classes for battle and cutscene sequences, with much content but little logic.
- **Replaceable:** Unity engine, uGUI, Timeline, .NET BCL, DOTween, TextMeshPro, Wwise, Nintendo SDK (`nn`, MessageStudio), and NEX/Pia plugins. About 3,000 types excluding BCL, 4,500 including it: 25%/38% of dump types and 20%/59% of method entries.
- **Neither category:** `SmartPoint` (174 types) is the studio's asset/component framework. Functionality must be replaced (asset loading, PlayerPrefs provider, render priorities), but it is not game content.
- **Data:** `XLSXContent` (417 types) and `DPData` (192 types) are generated table layers/data models, tied to file formats (save format: `docs/save-format.md`). This is mostly layout work, not logic.
- **Online:** 276 game-specific networking types plus 528 middleware types (NEX, Pia, Ilca) can be stubbed for an offline target.

### Interpretation

- At name level, opendpr almost completely matches the dump. Gaps are Wwise (separate `Dpr_WwiseProject` and only eight `AK` files), DOTween portions, and about 47 global game types.
- **This does not mean the logic is finished.** A name match says nothing about method bodies, correctness, or completeness. About 310,600 lines for roughly 43,400 game-type method entries suggests populated bodies, but that was not checked here.
- Counts cannot establish whether files are handwritten; opendpr's README describes both handwritten and script-generated code. Reuse requires a separate license/quality review (`docs/opendpr-machbarkeit.md`).
- Effort implication: Reconstruction is large by dump size (about 6,200 types); remaining work is less about class count than verification, executability, and replacing middleware.
