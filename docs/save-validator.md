# Save Validator (`scripts/bdsp_save.py`)

## Purpose
Standalone, dependency-free validator for BDSP `SaveData.bin` and `Backup.bin` (same format).
It reads the version and size, computes the MD5 hash as the game does according to `docs/save-spec-entwurf.md`, and includes the top-level field table (offset, size, name, type) for version 0x34.
The structure comes solely from our specification; no third-party code was reused.

## Usage
```
python3 scripts/bdsp_save.py check <datei> [--fields]
python3 scripts/bdsp_save.py dump-fields
python3 scripts/bdsp_save.py fix-hash <eingabe> <ausgabe>
python3 -m unittest discover -s scripts/tests -v
```
- `check`: exit code 0 = size and hash match, 1 = mismatch, 2 = cannot validate (e.g. unknown or truncated version).
- `fix-hash` writes only to a new output file (existing files and the input are never overwritten).

## Limitations
- Only version, size, and hash are checked; nested structure contents and Pokémon encoding are not evaluated.
- Versions > 0x34 are unknown and reported as such, not guessed. The game itself does not check versions < 0x25; the validator reports “cannot validate.”
- The game pads files that are too short with zeros when loading; the validator treats truncated files as errors.
- An exact match between older versions' file sizes and the BINARY_SIZE table is verified against a real file only for 0x34.
- The field table is contiguous and totals 0xEF0A4; sizes may include padding (see open points in the spec).
- Negative version values are read as signed `int` (as in the spec) and treated as “< 0x25.” Whether the game compares them as signed is unverified.

## C# port (`unity/Assets/Scripts/Save`, assembly `Xnu.Save`)
- Same logic as pure C# classes without a UnityEngine dependency (netstandard2.1, `System.Security.Cryptography.MD5`):
  `SaveLayout` (constants, size table, field table with name/offset/size/type), `SaveValidator` (`ReadHeader`, `ExpectedSize`,
  `ComputeHash`, `StoredHash`, `VerifyHash`, `Validate` with `SaveValidationResult` including an error list), and `SaveWriter.FixHash`.
- `FixHash` works on byte arrays and returns a new copy; inputs are never modified. File I/O is intentionally not included.
- Error behavior matches Python: `SaveFormatException` for too-short, truncated, or unknown versions; `Validate` never throws,
  but gathers findings (`HashValid`/`SizeOk` are `null` when validation is not possible).
- Tests: `unity/Assets/Tests/EditMode/SaveValidatorTests.cs` (NUnit, synthetic bytes only, mirrors Python tests). They were run outside Unity
  in a throwaway project using `dotnet test` (21 passing); additionally, version, size, hash status, and `FixHash` results match the Python implementation on synthetic cases, and local `SaveData.bin`/`Backup.bin` are recognized as valid in read-only checks (version 0x34, 979108 bytes). Running the tests in the Unity Editor (`run_tests`) is still pending.

Write path (`SaveData`, `SaveFileIO`), directory conventions, and export: see `docs/save-kompatibilitaet.md`.
